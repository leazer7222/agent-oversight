# Facility Researcher

Capability modules for the pool-acquisition pipeline: discovery, evidence-bound
enrichment, deterministic triage and prioritisation. Registered as the agent
identity `{tenant}.facility-researcher` (child of
`{tenant}.facility-acquisition-controller`), executed by the shared worker in
`agents/teams/swim-sourcing/worker.py`. One process, three identities, no
inter-agent protocol: the job queue is the only channel.

| Module | What it does | LLM |
|---|---|---|
| `../facility-discovery-agent/discovery.py` | Places Text Search (live) or recorded fixtures (`source='fixture'`); dedup; structural request ceiling | no |
| `enrich.py` | extracts facts and contacts from a facility page; **every value needs a verbatim evidence span found in the page, checked in code** | yes (`claude-haiku-5-5`) |
| `../facility-qualification-agent/scoring.py` | deterministic weighted score, completeness, open questions | no |
| `triage.py` | four-state triage (`contact_first` / `research_further` / `not_currently_suitable` / `disqualified`), hard gates, recommended channel | no |

Owner: `reformai`. Design: `docs/reviews/pool-acquisition-final-design.md` (B.2, D).

Fixtures: `fixtures/site_pages.json` are RECORDED, labelled pages generated by
`fixtures/build_site_pages.py`. They are not real websites.

Tests: `agents/tests/test_discovery.py`, `test_qualification.py`, `test_prototype_e2e.py`.
