## Key audit findings (evidence-backed)
1. **No authentication or authorization exists.** All 28 API routes use the service-role client
   (`src/lib/supabase/server.ts:30`), bypassing RLS. No `middleware.ts`, no login, no roles.
   `company_id` is an optional query param (`api/agents/route.ts:36`), not a boundary.
   Live probe: `GET https://agent-oversight.vercel.app/dashboard` -> **200 unauthenticated**.
2. **Human approvals are unauthenticated.** `ratified_by` is a free-text body field
   (`api/scoping/[feature]/gate-a/route.ts:29`). The validate -> content-hash -> freeze pattern
   itself is excellent and worth reusing; the identity is not.
3. **`provider_accounts` has no credential storage** (`008_ai_ops_tables.sql:2-15`) - quota/plan
   metadata only. All 7 Anthropic call sites read a global `ANTHROPIC_API_KEY`. Tenant credential
   routing must be built from scratch.
4. **No agentic loop anywhere.** Every agent is a single-shot forced-tool structured-output call.
   This matches the requested bounded-workflow preference - do not introduce a loop.
5. **Budget governance records but does not enforce.** `budget.ts:66-132` hardcodes
   `hard_limit_usd: null`; `agents.cost_limit_usd` is referenced only in a types file.
6. **Nothing runs unattended.** `agents/teams/agile/worker.py:11` is "run locally per work session";
   no `.github/workflows`, no cron, no hosted worker. `claim_intake_job()` has a correct
   `FOR UPDATE SKIP LOCKED` claim but no lease/heartbeat/retry.
7. **Production read APIs are broken.** `GET /api/agents` -> 500 `TypeError: fetch failed`, while
   Supabase itself answers correctly (REST root 401 = up). Suspect Vercel env vars.
8. `inngest` and `resend` are in `package.json` dependencies with **zero usages** in `src/`.
9. Deploy-target ambiguity: `netlify.toml` present, but docs/LESSONS say prod is Vercel.
10. **Platform-boundary tension:** `PLATFORM_ARCHITECTURE.md:56-74,135-157` refuses orchestration and
    domain content in the control plane, yet `product_graph`, `platform.feature_lifecycle`, and
    `agile_intake_jobs` already live there. Recommended Option 2 (dedicated `swim_sourcing` schema as
    an extraction seam) with the deviation documented.

## New lessons (candidates for LESSONS_LEARNED)
- Dependencies in `package.json` are not capabilities. `inngest` and `resend` were both installed
  with zero usages - a README-level audit would have scored "email: available".
- "Tenant isolation" in an architecture doc is doctrine, not a control. Verify by asking which code
  path resolves the tenant: if it is a query parameter, there is no isolation.
- Probe production directly during an audit. Two cheap curl calls established that the dashboard is
  publicly readable and that the read APIs are broken - neither was discoverable from source.
