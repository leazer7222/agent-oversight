## Addendum - End-to-end validation found (and fixed) the REAL bug: BA wasn't consuming CCA resolution

Re-validated the original Partner/Admin failure end-to-end (not just CCA unit). The CCA fix alone did
NOT fix it - the bug MOVED from "CCA doesn't know Partner/Admin exist" to "BA doesn't deterministically
use what CCA knows."

Evidence: latest CCA artifact has Partner->[cbc:entity:partner], Admin->[cbc:actor:admin], partners
entity + admin actor present. But Habi concepts CON-0011 Partner and CON-0012 Admin had
maps_to_codebase=[] (Property Listing mapped correctly, proving the BA *can* map - it just guesses via LLM).

Root cause: the BA populated maps_to_codebase from (a) concept_resolution[noun] (only present if that
noun was in concepts_to_check at CCA-run time) and (b) the LLM's cbc_refs. It NEVER did a deterministic
name-match of the concept title against entities[]/actors[]. So when the Habi CCA run used Habi-specific
concepts_to_check (no Partner/Admin) and the LLM didn't guess, Partner/Admin fell through to [].

Fixes applied (BA side):
1. **Deterministic name-match** (ba-scoping-agent/agent.py): added `_norm` (mirrors CCA cbc
   normalization) and a normalized entity/actor name index. maps_to_codebase now: concept_resolution[noun]
   -> ELSE exact normalized name-match vs entities/actors -> ELSE LLM cbc_refs. Unit-validated:
   Partner->cbc:entity:partner, Admin->cbc:actor:admin, Property Listing->cbc:entity:property_listing,
   Partner Project Details->cbc:entity:partner_project_detail (fixes the prior mis-map), even with EMPTY
   concept_resolution (the failure case).
2. **Reuse backfill** (migration 038 graph_set_maps_to_codebase): when a reused concept has empty
   maps_to_codebase and we have a deterministic match, backfill it (proposed concepts only).
3. **Provenance** (FEAT node + product-graph.schema.json): record codebase_context_artifact_id +
   top-level scoped_against already carried it. FEAT-0008 now records scoped_against{commit, artifact_id}.

Schema regression I introduced + fixed: first added scoped_against as a nested object in the FEATURE
node node_attributes -> broke product-graph.schema.json validation (feature_node allows only
scoped_against_commit/notes/clarification_brief_artifact_id). Reverted to a flat
codebase_context_artifact_id key + added that key to the feature_node schema.
