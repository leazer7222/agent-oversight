## Addendum - PCA repurposed as the Agile front door (intake normalization)

Reframed the Product Clarification Agent from a one-line-idea question generator into an
**intake-normalization agent** (the Agile front door). Clarification is now CONDITIONAL.
Plan: `docs/agile-pca-integration-plan.md`. Built and smoke-tested all 6 steps end-to-end.

Architecture: raw intake -> text adapters -> canonical Intake Package -> Intake Classifier
(writes a LOGGED `intake_assessment` artifact first, every run) -> conditional clarification
-> Brief synthesis (writes `clarification_brief` only when FINAL) -> handoff (feature_intent
+ concepts_to_check) to CCA/BA.

Key principle locked: **PCA does not always ask questions - only when the intake package
cannot confidently satisfy the Clarification Brief contract.** Decision is proceed_direct |
clarify | block, recorded in the auditable intake_assessment before the lifecycle advances.

Steps done:
1. Migration **033** (`agent_outputs.output_type` += `intake_assessment`, `clarification_brief`).
   Linted, APPLIED to prod, verified via pg_constraint.
2. Schemas: new `intake-package.schema.json`, `intake-assessment.schema.json`; edited
   `clarification-brief.schema.json` (+optional `handoff`, `open_questions` minItems 1->0,
   `metadata.intake_assessment_artifact_id`, `design_inputs[]`). All validated.
3. PCA runtime (`agent.py`): legacy class preserved; new pipeline added (build_sources,
   run_intake, classifier + conditional synthesis, BA/CCA-aligned Supabase + telemetry).
4. Grounding bundle `docs/workspaces/reformai-product/` (PRODUCT.md, DOMAIN.md, agile-v1.json).
5. BA `agent.py`: `--clarification-artifact-id` -> stamps `feat_attrs.clarification_brief_artifact_id`
   (the field the Scoping dashboard reads). One-liner, no frontend change.
6. Orchestrator (`run.py`): rewritten as lifecycle coordinator - drives PCA via `run_intake`
   with `parent_run_id`, routes decision to FSM next-state, emits the handoff.
