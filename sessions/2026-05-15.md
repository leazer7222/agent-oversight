## Issues encountered, root causes, and solutions

### 1. ANTHROPIC_API_KEY not visible to running process

**What happened:** Running the PCA via PowerShell failed with an Anthropic auth error even though the key was set in Windows user environment variables.

**Why built this way:** The key was added to the Windows user environment after Claude Code was already open. Windows user env vars only apply to processes started AFTER the change is made — running processes don't see new vars.

**Solution:** Load the key into the current PowerShell session before running:
```powershell
$env:ANTHROPIC_API_KEY = [System.Environment]::GetEnvironmentVariable('ANTHROPIC_API_KEY', 'User')
```
Long-term: restart Claude Code after setting env vars so it inherits them automatically.

### 2. Unicode print error on Windows (cp1252)

**What happened:** `run.py` crashed printing the markdown brief because the LLM used emoji (🟡) in its output, which cp1252 (Windows console default) can't encode.

**Why built this way:** `md_path.read_text()` returns a Python string with full Unicode; `print()` uses the console's default encoding, which on Windows is cp1252, not UTF-8.

**Solution:** Encode with replacement before printing:
```python
print(md_path.read_text(encoding="utf-8").encode(sys.stdout.encoding, errors="replace").decode(sys.stdout.encoding))
```

### 3. Dashboard timestamps showing UTC instead of CST

**What happened:** All dates in the dashboard (runs, agents, errors) showed in UTC because the server renders on Vercel (UTC timezone).

**Why built this way:** `new Date(...).toLocaleString()` with no options uses the runtime's local timezone. On a developer's machine this looks fine (it matches their local time), but Vercel runs in UTC so it showed UTC in production.

**Solution:** Added `formatDateTime`, `formatDate`, `formatTime` helpers to `src/lib/utils.ts` with `timeZone: 'America/Chicago'` and replaced all bare `toLocaleString()` calls across 6 dashboard pages.

### 4. Provider quota snapshots expiring overnight (8h TTL)

**What happened:** User-confirmed quota snapshots expired at 2 AM CST and the dashboard showed stale/blank data by morning.

**Why built this way:** The original 8h TTL was conservative — we didn't want stale data influencing decisions too long. But in practice, quota doesn't change that fast on a subscription plan, and the TTL was too short to survive a full work cycle.

**Solution:** Increased `user_confirmed` snapshot TTL from 8h to 24h in `src/app/api/ai-ops/quota-snapshot/route.ts`.

### 5. Recommendation engine recommending Claude at 0% quota

**What happened:** AI Ops recommended "Prioritize Claude today" even though Claude was confirmed at 0% quota. OpenAI was at 89%.

**Why built this way:** The `scoreProvider()` function only evaluated quota when BOTH `quota_remaining_pct` AND `hours_until_reset` were non-null. Claude had no reset schedule configured (`hours_until_reset = null`), so the quota check was skipped entirely and it fell through to the neutral `0.5` score. Claude then won by a hair on workload fit (0.80 vs 0.75 for general tasks).

**Solution:** Decoupled quota scoring from reset schedule. `quota_remaining_pct = 0` now always scores `0.0` regardless of whether reset time is known. Also fixed `buildReasons()` to surface "Quota exhausted" in the reasons text.

### 6. Quota-sync agent: SUPABASE_SERVICE_ROLE_KEY was wrong in machine env

**What happened:** Quota sync POSTs to Supabase were returning 401 Unauthorized.

**Why built this way:** The key was manually added to Windows user environment variables at some point, but the wrong key (the anon/public key, 105 chars) was stored instead of the service role key (219 chars). They look similar (both are JWTs starting with `eyJ`) so it wasn't obvious.

**Solution:** Updated the machine env var with the correct service role key from `.env.local`. Also added dotenv loading to `quota_sync.py` so it reads `.env.local` directly as a fallback, making it resilient to machine env being wrong.

---

### 7. Quota-sync agent: Claude OAuth refresh URL returned 404

**What happened:** The script was calling `https://claude.ai/api/oauth/token` to refresh its Claude OAuth token, getting a 404. This broke the Claude quota fetch silently overnight.

**Why built this way:** The refresh URL was hardcoded when the script was written. Claude's OAuth endpoints have changed since then. The script was doing its own token refresh instead of trusting Claude Desktop/CLI to manage the token.

**Solution:** Removed the in-script refresh logic entirely. The script now reads whatever token is currently in `~/.claude/.credentials.json` and proceeds — if it's expired, the API call fails gracefully. Token management is delegated to `claude login` (Claude CLI) which is the authoritative source.

**Ongoing requirement:** Periodically run `claude login` in a terminal (not inside Claude Code — open a separate cmd/PowerShell window and run `claude login`) to keep the OAuth token fresh. The token lasts ~2 days.

### 8. Quota-sync agent: telemetry 401 (wrong secret + stale URL)

**What happened:** The oversight telemetry at the end of quota_sync.py was failing with 401. Two causes:
1. The `OVERSIGHT_SECRET` env var check didn't include `AGENT_OVERSIGHT_SECRET` (the correct var name for production)
2. `OVERSIGHT_URL` was hardcoded to the old Netlify URL (`agentoversight.netlify.app`) instead of the current Vercel URL

**Why built this way:** The script was written before the Vercel migration, and the secret env var naming convention (`AGENT_OVERSIGHT_SECRET`) was standardized later in LESSONS_LEARNED but not retroactively applied to this script.

**Solution:** Updated `OVERSIGHT_URL` default to `https://agent-oversight.vercel.app` and added `AGENT_OVERSIGHT_SECRET` as the first fallback in the secret resolution chain.
